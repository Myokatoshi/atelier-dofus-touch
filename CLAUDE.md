# Atelier Touch : notes pour Claude

- Projet séparé de l'Atelier Dofus 3 (dépôt `atelier-dofus`) : ne rien partager avec lui (ni code, ni base). Application pour **Dofus Touch**, serveur de référence **Kelerog** (le serveur ne change que l'étiquette des relevés : `S.settings.server`).
- Mise en ligne : chaque push sur `main` est recopié sur `gh-pages` (workflow « Mise en ligne »), publié sur https://myokatoshi.github.io/atelier-dofus-touch/.
- Mise à jour des données du jeu : PAS de workflow GitHub possible (le serveur de données d'Ankama renvoie 403 aux machines de GitHub Actions ; essayé le 24/11/2026). Les mettre à jour depuis une session Claude (le réseau de l'environnement « atelier-dofus » y a accès) : `fetch_data.py --force`, `build_data.py`, `fetch_worldmap.py`, puis incrémenter `VERSION` de `sw.js`, commit et push. `build_data.py` est déterministe : pas de changement = rien à publier.
- Même domaine (myokatoshi.github.io) que l'Atelier Dofus 3 : le service worker ne supprime que les caches `touch-…` ; stockage local sous la seule clé `atelier-touch`.
- Application web statique (PWA), sans build : `index.html`, `css/app.css`, `js/*.js`, `sw.js`. Pas de compte ni de serveur : tout est dans `localStorage["atelier-touch"]` (`S` dans `js/core.js` : réglages, prix, suivis, inventaire, plan, métiers, builds, progression des quêtes/succès/donjons, filtres `S.ui`). Export/import dans Réglages.
- À chaque changement de l'appli, incrémenter `VERSION` dans `sw.js` (`touch-vN`), sinon les utilisateurs gardent l'ancienne version en cache.
- Commits signés avec l'adresse anonyme GitHub (`Myokatoshi@users.noreply.github.com`, dans `.git/config`), jamais l'adresse personnelle.
- L'utilisateur ne veut pas gérer la technique : faire soi-même tout ce qui est possible.
- Interface en français, tutoiement, thème sombre uniquement. Vert = hausse (`.pos`, `.chip.up`), rouge = baisse (`.neg`, `.chip.down`).
- Téléphone (≤ 720 px) : aucun défilement horizontal, aucun texte qui sort de sa case ; tableaux `.tablewrap` avec `data-label` sur chaque `td` (cartes empilées, cellule principale `.mc`, `.hide-m` masque), listes `.li` (empilées sous 560 px). Vérifier avec un audit Playwright en 360 px et iPhone 13.

## Fichiers JS (chargés dans cet ordre, fonctions globales)
- `core.js` : données (`need("monsters", …)` charge `data/<nom>.json`), `item(id)`, icônes (`icon()`, `monImg()`, `itemImg(iconId)`, `monUrl(id)`, `spellImg()`, `jobImg()` : **CDN officiel** `D.core.assets` + `gfx/...` ; `static.ankama.com` refuse les images affichées sur un autre site, ne pas l'utiliser ni contourner sa protection), effets (`fxText()`, `fxList()`), prix (`setPrice(id, p1, p10, p100)`, `price(id)` = prix unitaire le plus bas des lots du dernier relevé, `trend()`), recettes (`recipe()`, `usedIn()`, `costOf()` achat ou craft le moins cher, `recipeCost()`), recherche (`find()`, `searchBox()`), navigation (`GROUPS` : 6 rubriques, `page(nom, {title, icon, intro, needs, render})`, adresse `#page/arg`), fiches (`sheet(type, fn)`, `openSheet(type, id)`, clic sur `data-item` / `data-mon` / `data-sheet="type:id"`).
- `ency.js` : Objets, Panoplies, Monstres, Familiers (`misc.json` `pets` : nourriture) ; fiches `item`, `set`, `mon` ; `dropsOf()`, `harvestOf()`, `critText()`, `priceChart()`, `priceForm()`. Fiche objet : « Demandé dans les quêtes » et fiche monstre : « Dans les quêtes » (`questNeeds()`, objectifs de `guide.json`), nourriture du familier / familiers nourris (`petsFedBy()`), estimation du brisage + lien `#brisage/<objet>`.
- `market.js` : Prix HDV (relevés, tournée), Crafts rentables (`craftRows()`, simulateur `#crafts/simu/<id>`), Brisage (`shatter()` : runes = ((niveau ÷ 100) × jet × poids + 1) ÷ poids si poids > 1, × coefficient ; poids `RUNE_W`).
- `prod.js` : Plan de craft (`planExpand()`, `planNeeds()`), Inventaire, Métiers (`JOB_XP` niveaux 1–100, `CRAFT_XP` XP par nombre de cases, bonus pack × 1,5), Liste de farm.
- `adventure.js` : Donjons, Quêtes, Succès, Carte ; fiches `dungeon`, `quest`, `achievement`. Carte (canvas) sur les **images officielles** du jeu : tuiles de 250 px `data/worldmap/<carte>/<échelle>/<n>.webp` (n = ligne × colonnes + colonne + 1, comme le client), icônes des repères `data/hints/<icône>.webp` (atlas officiel `gfx/icons/assets`), toutes deux produites par `tools/fetch_worldmap.py` depuis le CDN officiel ; 7 cartes (`world.json` `maps` : Monde des Douze, Cavernes des Givrefoux, égouts de Bonta et de Brâkmar, Village de la Canopée, Château d'Harebourg, Archipel d'Albuera ; `grids` = cases des cartes autres que le Monde des Douze, `grid` = Monde des Douze) ; une case (x, y) a son centre en origine + (x + ½) × largeur de case (cases non carrées : 69,5 × 49,7 px au Monde des Douze, rapport `k`) ; adresses `#carte/sub/<sous-zone>`, `#carte/res/<ressource>`, `#carte/mon/<monstre>`, `#carte/pos/x/y[/carte]` ; la recherche et la surbrillance passent sur la carte qui contient le plus de cases. Entrées de donjons en intérieur (carte -1) placées sur le Monde des Douze (mêmes coordonnées).
- `guide.js` : page Guide (première page d'Aventure) : trames de quêtes à suivre pas à pas. « Parcours conseillé » = catégories du jeu Tutoriel, Quêtes principales et « Quêtes prioritaires » (Astrub, Monde des Douze, donjons, Château d'Allister, Frigost…, liste `GD_MAIN`) ; toute autre catégorie ; « Les Dofus » (chaque Dofus : quêtes, monstres qui le lâchent, recette, succès, case « obtenu » `S.dofus`) ; « Ma trame » (`S.ui.myTrame`, quêtes choisies et ordonnées). Ordre : quêtes précédentes de Papycha (API, si chargée) puis niveau puis ordre du jeu (`gdSort`). Chaque quête se déplie (`GD.open`, gardé au redessin) : étapes (texte du jeu), objectifs cochables (`S.qobj`, tous cochés = quête faite `S.quests`) avec PNJ, objets à ramener (stock, prix), monstres, âmes, coordonnées (lien carte), récompenses, prérequis (niveau, quêtes précédentes Papycha). « Courses et objectifs restants » : objets échangeables à ramener (moins le stock, prix, + Plan, tournée des prix, liste de farm), objets de quête à part, à fabriquer, âmes, monstres. Données : `data/guide.json` (`build_data.py` : étapes et objectifs détaillés, catégories ordonnées, noms des PNJ, `texts` = textes des objectifs « action en jeu » et noms des cartes à découvrir, demandés au serveur du jeu par `fetch_data.py` via `POST /data/text {"ids": […]}` → `.cache/raw/QuestObjectiveTexts.json`). Point de départ d'une quête = premier objectif avec coordonnées (`gdStart`). Le jeu ne publie pas les conditions de départ des quêtes : prérequis = niveau + quêtes précédentes de Papycha.
- `build.js` : Builds (poupée, points, panoplies, totaux), Sorts (rangs, effets, dégâts estimés) ; fiche `spell`.
- `home.js` : Accueil (dont « Mon guide » : progression du parcours conseillé, prochaine quête, Dofus obtenus), Almanax (`almId(date)`, `almDay()`, `almOfferNext()`, `almOfferDays()`), Guides, Réglages ; `papyAll(famille)` (API Papycha).

## Données (`data/`, générées)
- `tools/fetch_data.py` : tables du jeu depuis le serveur officiel (`config.json` → `dataUrl` = `https://dt-proxy-production-login.ankama-games.com`, `POST /data/map?lang=fr {"class": "Items"}`), dans `.cache/raw/` (non publié). `tools/build_data.py` écrit `core.json` (objets, types, effets, panoplies, recettes, métiers, récoltes), `monsters.json`, `world.json` (zones, sous-zones, cases de la carte, donjons, repères), `spells.json`, `quests.json` (quêtes, succès, défis), `almanax.json`, `desc.json`, `misc.json`. Formats : voir les commentaires de `build_data.py`. Puis `tools/fetch_worldmap.py` (tuiles et icônes de la carte, ~2 900 fichiers, ne télécharge que ce qui manque). Le service worker garde `data/worldmap/` et `data/hints/` dans le cache `touch-img` (pas retéléchargés à chaque version).
- Almanax : l'entrée du calendrier suit la date (19/11/2026 = entrée 66, relevé en jeu et recoupé) ; offrande = quête « Offrande à … » dont l'objectif va voir le Méryde du jour ; décalage corrigeable dans l'appli (`S.settings.almOffset`).
- Pas de source de prix automatique pour Dofus Touch (Kamamaster ne suit que Dofus 3) : les prix viennent des relevés de l'utilisateur.
- DofusDB : licence LPNC-IA (interdit de fournir ses données à une IA) → ne pas l'utiliser.

## Papycha (https://papycha.fr)
- Politique : extraction, base locale, miroir, republication **interdits** ; l'API publique `https://papycha.fr/wp-json/papycha-public/v1/` (familles `quests`, `dungeons`, `paths`, `taxonomy`, `capabilities`) est autorisée avec attribution (nom + lien vers la page). L'appli l'interroge en direct depuis le navigateur (CORS ouvert), garde les réponses en mémoire le temps de la session seulement, et affiche « Source : Papycha » + lien. Ne jamais recopier ses textes ni stocker ses pages.
